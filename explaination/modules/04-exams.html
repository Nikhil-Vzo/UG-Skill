High-Stakes Exams & Proctoring

Real-time anti-cheat signals using WebSockets and event streaming

The Silent Exam Hall Metaphor

During a high-stakes exam, a student's webcam and tab actions are monitored live. Rather than refreshing a database every second (which would crash the server), the app operates like a silent exam hall:

🔌

The Dedicated Line (WebSockets)

A continuous open pipe connects the browser directly to the server. Information flows instantly in both directions with zero request delays.

🎟️

Exam Channels (Namespaces)

A special `/tracking` namespace separates tracking alerts from generic chat or exam question updates, keeping traffic clean.

💓

Keep-Alive check (Heartbeat)

The browser sends a heartbeat every 30 seconds. If it stops, the system knows the student disconnected or closed the window.

Behind the Scenes: Streaming the Flags

Let's trace how the server handles anti-cheat event alerts via the WebSocket socket listener:

CODE 
socket.on('flag:event', async ({ attemptId, eventType, severity, metadata }) => {
  if (!attemptId || !eventType || !severity) {
    socket.emit('error', { message: 'Missing fields' });
    return;
  }
  const room = `tracking:${attemptId}`;
  const alert = { attemptId, eventType, severity, userId, timestamp: new Date().toISOString() };
  try {
    const attempt = await examAttemptRepository.findAttemptById(attemptId);
    await proctoringService.ingestEvent({
      attemptId, examId: attempt.examId, studentId: attempt.studentId,
      type: normalizeEventType(eventType), severity: severity.toUpperCase()
    });
  } catch (err) { logger.error('Failed to persist flag', err); }
  // Broadcast alerts
  trackingNS.to(room).emit('flag:alert', alert);
  trackingNS.to('admin:monitoring').emit('flag:alert', alert);
});
PLAIN ENGLISH

Listen for a client incoming 'flag:event' message (e.g. face missing)...

Ensure we received the attempt ID, the event type, and severity...

If fields are missing, send an error reply back to that socket...

Stop execution of this event handler.

End validation check.

Format the room channel name specific to this student's exam session...

Construct a structured alert payload containing user, event, and current time...

Start a try block to save this violation in the database...

Find the specific exam session record to load context...

Save the violation event to MongoDB (e.g. tab-switch, phone-detected)...

Pass the normalized types, exam IDs, and severity levels.

End database storage parameters.

If database ingestion fails, print an error to the server console log...

Send alerts in real-time to other listeners...

Send (broadcast) the alert to the instructor monitoring the specific student...

Also broadcast the alert to the global admin dashboard for main dashboard logs.

Done handling the flag event.
