# LOGGED BY CODEX - PROCTORING SYSTEM IMPLEMENTATION LOG

## INITIAL IMPLEMENTATION PLAN (Drafted by Antigravity for Codex)

### Goal: Industry-Level Real-Time AI Proctoring System
This system will utilize Edge AI (MediaPipe + TF.js) for instantaneous cheating detection, real-time snapshot persistence in MongoDB, and a centralized Admin Monitoring Hub.

---

### Step 1: Core Dependency Injection
We will integrate the best-in-class open-source libraries identified from industry benchmarks (and the repositories provided):
- `@mediapipe/face_mesh`: For 468-point landmark tracking (Gaze, Head Pose, Mouth Movement).
- `@tensorflow-models/coco-ssd`: For Object Detection (Specifically "Cell Phone").
- `socket.io-client`: For real-time event bridging to the Admin HUD.

### Step 2: The "ProctoringEngine" Singleton
Create a specialized service that abstracts the AI complexity:
- **Initialization**: Load models asynchronously on exam entry.
- **Detector Loop**: Run at ~5 FPS to detect:
    - `GazeTracking`: If iris position shifts > 30% from center for > 2 seconds.
    - `FaceCount`: If faces != 1.
    - `ObjectDetection`: If `class === 'cell phone'` with confidence > 0.6.
    - `TalkDetection`: If mouth aspect ratio (MAR) exceeds threshold.

### Step 3: UI/UX (The Student HUD)
- **Floating Preview**: A `PremiumCard` containing a live webcam feed.
- **Incident Warnings**: Local UI overlays (e.g., "Face not detected", "Phone detected") to provide instant feedback.
- **Auto-Snapshot**: When a violation is detected locally, trigger a high-res canvas capture.

### Step 4: Data Persistence (MongoDB Hardening)
- **Endpoint**: `POST /api/proctoring/incident`
- **Payload**: `{ attemptId, type, severity, snapshotBase64, aiMetadata }`
- **Storage**: Save to `ProctoringEventModel` in MongoDB. Ensure base64 images are stored (or optimized via GridFS/S3 if volume grows).

### Step 5: Admin Live Monitoring "War Room"
- **Grid View**: A list of all active attempts.
- **Real-Time Push**: Socket.io emits `incident:new` to the admin room.
- **Instant Action**: Buttons for `[Warn Student]`, `[Pause Exam]`, `[Terminate]`.

[2026-05-09 02:20] [Codex] Phase 0 research complete. Local files implementation_plan.md and task.md were not present in the workspace root, so I used the user-provided plan and this existing log as the working source of truth. Open-source findings:
- vardanagarwal/Proctoring-AI: Eye tracking computes eyeball position by comparing pupil/contour center against eye ROI endpoints: x_ratio = (left_edge - cx) / (cx - right_edge), y_ratio = (cy - top_edge) / (bottom_edge - cy), then flags left/right/up when ratios cross extreme thresholds. Mouth opening records baseline vertical distances between paired upper/lower lip landmarks, then flags mouth open when most outer and inner pairs exceed baseline by small pixel deltas. Person/phone detection counts COCO/YOLO classes where person=0 and cell phone=67.
- narender-rk10/MyProctor.ai and narender-rk10/proctoring: Best reusable product logic is the event taxonomy and capture cadence: tab/window logs, audio snapshots every 5 seconds, phone detection, more-than-one-person detection, gaze estimation, and periodic student image logs. The Python package exposes base64 image analysis with statuses for mobile, person count, head movement, and eye movement.
- openedx/edx-proctoring: Strong reference for platform integration rather than CV math. The useful pattern is treating proctoring as an exam subsystem with attempt status, provider/config separation, auditability, and admin review/override flows.

Integration plan for ugskill-web/src/lib/proctoring/ProctoringEngine.ts:
- Use MediaPipe FaceLandmarker in the browser for face landmarks and blendshapes. Convert Vardan's endpoint-ratio idea into normalized iris ratios: irisX = (irisCenterX - eyeLeftX) / (eyeRightX - eyeLeftX), irisY = (irisCenterY - eyeTopY) / (eyeBottomY - eyeTopY). Flag gaze_away only after sustained off-center ratios/head yaw for >2 seconds.
- Use Mouth Aspect Ratio instead of raw pixel deltas: MAR = mean(vertical lip distances) / mouth width. Treat talking as sustained MAR > 0.4 plus oscillation over a short sample window, reducing false positives from a single yawn or static open mouth.
- Use COCO-SSD for person and cell-phone detection with confidence thresholds, mapping >1 person to CRITICAL and phone to HIGH/CRITICAL depending on confidence.
- Add adaptive FPS: normal state near 2 FPS, suspicious state near 10 FPS, and report incidents through an onIncident callback so ExamInterface can show a webcam HUD, toast warnings, emit socket events, and capture 720p evidence frames.
